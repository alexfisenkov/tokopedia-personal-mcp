# Архитектура

Локальный stdio MCP на TypeScript, официальный MCP SDK, SQLite из Node >=24.
Одна база одного покупателя. Исходники ведутся в GitHub, пользовательские
снимки хранятся в выделенной локальной папке.

## Слои

- domain.ts: схемы order / shipment / transaction / chat / product.
- store.ts: атомарный импорт, стабильный ключ kind+id, история версий, поиск.
- service.ts: состояние набора данных, чтение, черновики сообщений и планы покупок.
- server.ts: MCP handlers, валидация, annotations, обработка ошибок.
- index.ts: stdio entry point, путь базы, завершение процесса.
- scripts/smoke.ts: MCP Client/Server по stdio на синтетических данных.

## Контракт данных

Каждая запись имеет kind, id и observedAt (ISO-8601 с часовым поясом).
Новая версия сохраняется вместе с предыдущими снимками. Повтор одного снимка
идемпотентен. Импорт атомарен. История хранит исходные версии и их SHA-256.
Каждая запись — полный снимок сущности, включая массивы сообщений и событий.
Текущая версия соответствует последнему полному снимку; прежние состояния
доступны в истории. Поиск и пагинация выполняются в SQLite.
Новые снимки чата сохраняют известные ID сообщений; снимки доставки — известные
события. Проверка целостности выполняется в той же транзакции, что и запись.

Поиск и фильтры работают по загруженному набору. Результаты содержат
provenance=manual_import. Статус сервера показывает размер набора и время
последнего импорта. Черновики сообщений и планы покупок имеют собственные
статусы DRAFT_NOT_SENT и PLAN_NOT_ORDERED.

## Развитие

Изменения исходников проходят через этот репозиторий. Проверка состоит из
типизации, тестов домена и хранилища, сборки и end-to-end MCP smoke.
GitHub Actions запускается вручную для согласованной версии.
